# **RF17 \- Publicar a frequência cardíaca no *broker***  
O sistema deve publicar no *broker* as leituras de frequência cardíaca recebidas da pulseira, para que os consumidores as recebam independentemente do coletor que as coletou.

Caso de Uso \- Publicar a frequência cardíaca no *broker*

| Campo | Descrição |
| :---- | :---- |
| Identificador | UC17 |
| Nome | Publicar a frequência cardíaca no *broker* |
| Ator principal | Coletor BLE |
| Pré-condição | Coletor ativo recebendo a frequência cardíaca (RF16); coletor conectado ao *broker* (RF11) |
| Pós-condição | Leituras publicadas no tópico da pulseira |

**História de usuário:**  
Como consumidor, quero receber a frequência cardíaca de cada pulseira em um único tópico, para acompanhar o pesquisador sem precisar saber qual coletor está conectado a ele.

**Critérios de aceitação:**

* As leituras devem ser publicadas em um tópico por pulseira, e não por coletor (ex.: pulseiras/{endereco}/frequencia-cardiaca).  
* A mensagem deve conter endereço da pulseira, identificador do coletor, frequência cardíaca em bpm, intervalos RR (quando houver) e *timestamp* da leitura.  
* Somente o coletor ativo, que detém a posse da pulseira (RF14), deve publicar as leituras, evitando dados duplicados durante o *handoff*.  
* As mensagens devem usar QoS 1, e o *timestamp* deve permitir que os consumidores descartem leituras repetidas.  
* Se o *broker* estiver indisponível, o sistema deve manter em memória até um número configurável de leituras e publicá-las em ordem ao reconectar, descartando as mais antigas quando o limite for atingido.  
* A falha no *broker* não deve interromper o recebimento da frequência cardíaca (RF16).
